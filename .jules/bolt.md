## 2024-05-18 - Hoist Invariant Strings and Short-circuit Iterative Matches
**Learning:** In list filtering operations like `.where()` that evaluate multiple string attributes (e.g., in `transactions_screen.dart`), constructing and transforming intermediate strings (e.g., using `?.toLowerCase()` or `.toString()`) inside the evaluation block for all fields simultaneously is incredibly inefficient. When combined with long lists of objects, redundant allocations skyrocket.
**Action:** Always hoist invariant transformations like the main query string (`query.toLowerCase()`) *outside* the iterative `.where()` loop. Inside the loop, evaluate string transformations lazily using a series of `if (<field>.toLowerCase().contains(q)) return true;` statements to short-circuit the execution path as soon as a match is found. This prevents computing properties further down the chain when a match occurs early.
