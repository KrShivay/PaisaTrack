## 2024-05-19 - Inefficient local filtering loops in Dart
**Learning:** Found an inefficient filtering loop in `lib/features/transactions/transactions_screen.dart`. When searching local transactions on the frontend, the code constructs multiple strings, calls `.toLowerCase()` repeatedly inside a loop on `TransactionListItem` fields, and checks `.contains()` unconditionally across all text fields. This allocates many small strings every keystroke on a potentially large dataset of transactions (even ones that might be `null`). Dart string manipulation in hot loops should be optimized by applying lazy/short-circuit evaluation to prevent allocations on fields that aren't matched. A `TransactionListItem` also contains many fields.
**Action:** Re-write the transaction local filtering logic. Prioritize early exit checks. Compute the lower-case search query once. For fields to search against, only evaluate `.toLowerCase().contains(q)` directly (with early return on first match using `||`) rather than concatenating them or checking all fields even if an earlier one matches. This avoids unnecessary object allocations and lowers CPU overhead on the UI thread.
