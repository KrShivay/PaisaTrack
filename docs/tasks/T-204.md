# T-204 — App-wide icon, design-language and screen redesign briefs

Plan: [docs/plans/ux-v2.md](../plans/ux-v2.md). Status: Proposed, planning
only — 2026-10-10. Scan evidence (path:line) is in plan section 2.

Conventions for every subtask below:

- Never write a raw `Icons.*`, `Color(0x…)`, `Colors.white/black`, literal
  `BorderRadius.circular(n)` or `isDark ? … : …` in files you own once the
  primitives exist; use `AppIcon/AppIcons`, `context.bloom`, `AppRadius`,
  `AppSpacing`, `BloomPressable`, `BloomChip`, `BloomCard`, `BloomStateView`.
- Preserve existing `ValueKey`s used by tests unless the task says otherwise.
- Screen acceptance baseline ("**baseline**"): widget test at 320x568 with
  `textScaler: TextScaler.linear(2.0)` in light and dark pumps without
  `tester.takeException()`; every tappable passes
  `meetsGuideline(androidTapTargetGuideline)` and
  `labeledTapTargetGuideline`; loading/empty/error states render through
  `BloomStateView`; refresh never re-shows a skeleton.
- Parallel groups: A (no deps), B (needs A items listed), C (needs A/B items
  listed, disjoint folders), D (needs C items listed), E (last). Haiku workers
  may run any same-group tasks concurrently.
