# T-135 — Net-spending contract

Closes T-100. One definition of "what counts as spending", read by budgets,
trends, category totals, and the assistant.

### T-135a — `net_amount` as the single aggregate input   [P1] [~L]
Files:    `lib/data/repositories/dashboard_repository.dart`,
          `lib/intelligence/insights_engine.dart`,
          `lib/intelligence/burn_rate_forecaster.dart`,
          `lib/intelligence/anomaly_detector.dart`
Depends:  T-134a, T-126 (calendar/eligibility predicate — must land first or
          together; both define spending and there can only be one answer)
Change:   Every aggregate reads `financial_events.net_amount` (paise) instead of
          summing `transactions.amount`. One conversion helper for the paise/REAL
          boundary during the T-130 transition — mixed-representation arithmetic
          is a real bug risk.
Tests:    Every existing dashboard, insight, and forecast total is byte-identical
          before and after for a fixture dataset with no links.
AC:       A refund reduces exactly one period's total by exactly one definition.
Note:     `~L`. Split per consumer if the diff grows.

### T-135b — Refund linking   [P1] [~M]
Files:    `lib/capture/event_correlator.dart`, review UI
Depends:  T-135a, T-134b
Change:   Auto-link at ≥0.90 (exact ref, or exact amount + same counterparty
          within 30 days with no other candidate) with an "linked automatically —
          undo" affordance. 0.60–0.90 or multiple candidates → a review card with
          ranked options; fail closed, unlinked. Support partial amounts on the
          link row and many refunds to one expense.
Tests:    Full, partial, and many-to-one refunds. Ambiguous case stays unlinked.
          No source transaction is mutated or deleted.
AC:       Refund auto-link precision ≥0.98.

### T-135c — Cash, transfers, and card bills   [P1] [~M]
Files:    `lib/data/repositories/dashboard_repository.dart`, transaction detail
Depends:  T-135a
Change:   ATM withdrawal is `kind='withdrawal'` — money moved to untracked cash,
          not an expense; excluded from category spending, shown on its own line.
          Self-transfers keep existing exclusion. **Credit-card bill payment is a
          transfer** (bank → card) and the card's purchases are the real
          expenses; counting both double-counts. Each exclusion needs visible
          copy explaining itself.
Tests:    A month with a card bill and its underlying purchases totals the
          purchases once.
AC:       Every exclusion is explained in the UI, not silent. Retroactive changes
          to a closed month are explained rather than silently restated.
Rationale: `docs/sms-intelligence-design.md` §7.3, §7.4.
