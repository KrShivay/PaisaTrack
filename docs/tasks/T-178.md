# T-178 — Grounded analysis, forecasts and assistant

Status: proposed / Backlog. Contract: [AI opportunities report](../reports/grounded-ai-opportunities.md).
Architecture: [proposed ADR 0011](../decisions/0011-evidence-backed-assistance.md).

Reuse existing engines. These tasks do not require a new LLM. Groom one child
before implementation; do not promote this whole parent to In Progress.

## T-178a — Evidence-linked insights and fair comparisons [P1]

- Depends: T-177a evidence/coverage audit; reliable full-period queries.
- Anchors: `InsightsEngine`, `FinancialCalendar`, `FinancialEligibility`,
  `NarrativeInsightGenerator`, insight repository/renderers.
- Define typed claims with evidence IDs, period, scope, coverage, calculation,
  result version and reason. Align assistant spending queries with canonical
  settled-spending eligibility and prove parity with Dashboard. Compare like
  periods, including same elapsed days
  for a partial month; distinguish observed increase from inferred cause.
- Rank/deduplicate useful findings. A model may select supported claim IDs;
  fixed rendering supplies facts/numbers. No unsupported narrative reaches UI.
- Acceptance: partial periods, zero denominator, missing source, refund/transfer
  exclusions, stale edit invalidation and invented qualitative claims tested.
  “Why?” opens supporting rows; dismissals survive recomputation.

## T-178b — Forecast ranges with evidence of usefulness [P2]

- Depends: T-178a coverage contract and reliable date/eligibility semantics.
- Anchors: `BurnRateForecaster`, `RecurringDetector`, baseline repository.
- Define observed spend versus projected remainder, known recurring commitments
  versus uncertain variable spend, and a data-sufficiency/abstention policy.
  Never count the same recurring payment in both components. Missing capture
  is unknown, not zero. Estimates never create settled transactions.
- Compare existing day-of-month median with simple recent/seasonal baselines
  using rolling-origin tests at actual 7-day/month-end horizons. Evaluate
  amount error and interval coverage/width; do not use future corrections in
  training snapshots. Select complexity only when it beats the baseline.
- Acceptance: sparse history, irregular income, changed habits, gaps, refunds,
  month boundaries, reproducibility and no-model fallback; report sample size
  and target-hardware latency. If ranges cannot be validated, suppress the
  precision claim and show insufficient history.
- Exclude balance/runway promises until fresh verified balances and obligations
  exist. Income minus captured expenses is not a bank balance.

## T-178c — Typed English/Hinglish questions over verified results [P2]

- Depends: T-178a; T-178b for forecast questions only.
- Anchors: `AssistantIntentClassifier`, `IntentValidator`,
  `AssistantQueryEngine`, `AnswerRenderer`, prompt catalogue.
- Add bounded question forms for supported claims and forecast explanations.
  Clarify ambiguous period/payee/category rather than guessing. Reuse T-096
  tolerant category resolution and T-151 states; do not duplicate their scope.
- Acceptance: Hinglish paraphrases, ambiguous dates, injection-like merchant
  text, unsupported advice, missing model, unavailable result and malformed
  outputs. Every number and factual claim maps to typed evidence. No model SQL.

## T-178d — Local quality and performance release gate [P1]

- Depends: T-178a–c and T-115 device baseline; reuse T-177f measurement plumbing.
- Measure claim precision/support coverage, useful/dismissed insights, repeated
  alerts, forecast error/interval calibration, intent accuracy and refusal
  quality, plus latency/memory. Report cohort/sample limitations.
- Acceptance: chronological real-data evaluation under ADR 0005, separate
  synthetic robustness tests, no private data in logs/export without explicit
  action; offline/missing-model/rollback and edit-invalidation tests pass.
- Ship validated calculations/templates first. Optional model ranking cannot
  block capture or make data sufficiency appear better than it is.

## Implementation checks

Fresh impact analysis before edits; focused and full tests, analyzer, graph diff,
privacy/schema doc updates and target-device evidence as applicable. All current
constraints in COLLABORATION.md and the assistant grounding contract apply.
