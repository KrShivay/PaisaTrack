  DB transaction
  ([`burn_rate_forecaster.dart:47-160`](../../lib/intelligence/burn_rate_forecaster.dart#L47)).
  It filters `currencyCode == 'INR'` (`:63`), averages exactly three trailing

  the remaining days after today (`:98`), emits an insight when

  sufficiency or abstention rule and no interval.

  ([`anomaly_detector.dart:21-212`](../../lib/intelligence/anomaly_detector.dart#L21));

  flag `anomalyAlertMinPeriods` (`:154`); verify which one wins before
  changing either.

- Existing tests to keep green: `test/intelligence/burn_rate_forecaster_test.dart`

### Backtest metrics (every one is computed by `forecast_metrics.dart`, b2)

Per cohort (history-length bucket x horizon [7-day, month-end] x currency),
with sample count and month-block bootstrap 95% CI: empirical 80% interval
coverage; MdAPE and MAPE on non-zero actuals (zero/near-zero reported
separately); pinball loss at q = 0.1 / 0.5 / 0.9 for the candidate and for each
baseline (current 3-month day-median, seasonal-naive); median interval
width / actual; suppression rate with per-reason counts. Anomalies: precision,
recall, false alerts per account-month, suppression rate, by history bucket.
Pass thresholds: the plan's tables (coverage 75-88%, MdAPE <= 25%, pinball no
worse than the better baseline, width/actual <= 1.0, suppression <= 60%,
identical payload on rerun; anomaly precision >= 90%, recall >= 80%, <= 1
false alert per account-month). A synthetic pass is never owner-data
acceptance.

**C** = b6 (needs b4, b5, b8). **D** = b7, b9 (need b6). **E** = b10
(optional, needs b7, b9 and a device).
