# T-165c — Integer-paise (minor-unit) migration

Status: Proposed, planning only — 2026-10-10. ADR draft:
[0033](../decisions/0033-integer-paise-amounts.md) (Proposed; needs owner
approval, it amends the frozen record contract). Parent: T-165 (board:
"Plan and ADR an integer-paise migration").

## Recommendation: do it BEFORE T-100c and T-190f

Refund netting, card liability and budgets sum and cap-compare amounts. Doing
them on `double` and migrating later means rewriting each twice. Order:
T-165c1-c5 (type, schema, dual-write, parity) first; module swaps c7-c11 for
dashboard / claim / insights / transactions repo before T-100c; T-100a/T-100b1
(no new sums) may run in parallel, but b1's cumulative cap must use the Money
helper (c1) rather than a third converter. T-190b2+ and T-098 start after c5.

**Schema-version collision:** [ADR 0034](../decisions/0034-sms-facts-store.md)
(T-207) also claims schema v21 for `sms_facts`. "v21/v22" in this file mean
"next free schema version"; whichever migration merges second takes v22 and
rebases its migration test. T-165c3 must read `schemaVersion` at start.

## Design

- `Money` (`lib/core/money.dart`): `final int minor; final String? currencyCode;
  final String? currencySymbol;` with `+ - compareTo`, `isZero`, `negate`,
  `sumOf(Iterable<Money>)` that throws on bucket mismatch (ADR 0017),
  `fromDecimalString(String, {currencyCode})` (exact, no double),
  `fromLegacyDouble(double, exp)` (via shortest decimal text; null if excess
  precision), `toLegacyDouble()` (dual-write only), `toDecimalString()`.
- `CurrencyExponent` (`lib/core/currency_exponent.dart`): table JPY/KRW/VND/
  CLP=0, KWD/BHD/OMR/JOD/TND=3, default 2; null/unknown = 2.
- Column plan (v21, additive): `transactions.amount_minor INTEGER`,
  `balance_after_minor INTEGER NULL`, `recurring_series.expected_amount_minor`,
  `last_amount_minor`. Backfill with one SQL `UPDATE` per exponent group inside
  the migration transaction; verify; abort on any excess-precision row.
  Trigger (like the payment-source insert trigger in `database.dart`) fills
  whichever of `amount`/`amount_minor` is NULL on insert so a missed writer
  cannot create a half-populated row during dual-write.
- Dual-read period: readers stay on REAL until their module swap lands; a
  debug/test-only assertion (c5) checks `amount_minor == round(amount*10^e)` on
  every repository read. Contract release (v22): stop writing REAL, drop only
  after owner approval and one clean release.
- Backup: header `archive_version` 4 adds `amount_minor`/`balance_after_minor`/
  series minors and still writes legacy `amount`. Restore handles v1-v3 (convert
  legacy decimal exactly) and v4 (cross-check, mismatch aborts, FK check after).
  Older apps restore v4 archives via the legacy field.
- Rollback: legacy columns complete until v22 => reader swaps revert in code;
  data rollback = ADR 0012 snapshot / backup.
- Constraints: ADR 0011 (deterministic arithmetic, models never set amounts);
  ADR 0017 (no cross-currency sums, no FX); raw SMS retention unchanged;
  delete-everything and reset must cover new columns (they are columns on
  existing tables, so existing wipe paths apply: assert in tests).
