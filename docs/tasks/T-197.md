# T-197 — Activity keeps its scroll position after an edit

## Owner bug (2026-10-03)

"If a transaction from last month is updated, the list scrolls back to the
top instead of staying at the last opened item."

## Scope

Root-cause the reset in `lib/features/transactions/transactions_screen.dart`
and `transactions_providers.dart` (keyset pagination "Load more", portrait and
short-height sliver layouts). After editing a row (category, note, parse
edit, not-a-transaction, swipe confirm/recategorize, undo) and returning, the
list keeps the already loaded pages and the same anchor item; the edited row
updates in place. If the row leaves the active filter, keep position at its
neighbours. No change to keyset query semantics or totals.

## Acceptance

Regression widget test: load 2+ pages, scroll to an older row, open detail,
edit, pop: same anchor visible, page count unchanged; both layouts; undo.
Full suite, analyze, format, detect-changes; physical check.

## Rollback

UI state only; revert the change.
