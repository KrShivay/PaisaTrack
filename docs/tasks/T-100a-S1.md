# T-100a-S1 — Read-only refund relationship preview

Status: Host-complete and independently reviewed. This bounded implementation
advances T-100a preparation;
it does not complete T-100a/b/c or approve persisted refund accounting.

## Scope

Read one persisted credit and propose prior eligible spending debits by exact
stored reference evidence, using the shared source-currency and eligibility
contracts. Return explicit missing, invalid, ambiguous, already-linked, and
over-cap outcomes. Retain source dates and amounts. Existing refund/reversal
relationships consume the purchase's remaining refundable amount once; corrupt,
duplicate, or conflicting relationships require review rather than guessed
arithmetic. No merchant-prefix or amount-only automatic match.

This repository is a preparation API with no production UI or ingestion caller.
It writes nothing and changes no aggregate. Pair arithmetic is not a calendar
net-spending result. Refund-period policy remains an unanswered owner decision.
Contract: [ADR 0026](../decisions/0026-read-only-refund-preview.md).

## Acceptance

- A database read snapshot returns original/refund dates, original gross amount,
  existing linked adjustment, proposed refund and remaining amount.
- Same-currency full/partial/many-refund cases, exact-reference ambiguity,
  invalid direction/lifecycle/source flags, excluded categories, missing rows,
  future purchase, reference disagreement and malformed links fail safely.
- Duplicate source-credit representations and repeated reads never double-count.
- Source rows, links, feedback and financial aggregates are identical before
  and after preview. Restart recomputes from persisted evidence.
- No schema, archive encoding, capture wiring, ownership or enablement change.
- Decimal cap comparisons remain exact within the declared six-place source
  precision; unsupported/display-unrepresentable amounts and oversized lookups
  abstain explicitly. This is not a change to currency denomination or storage.
- Focused tests, full serial Flutter suite including encrypted migration,
  analyzer, changed-file formatter, America/New_York focused tests, documentation
  links and diff checks pass. Sol independently reviews Luna's implementation;
  refreshed GitNexus scans include all added symbols before commit.

## Dependencies and follow-ups

Reuse [source audit](../reports/T-100a-refund-source-audit.md),
[T-100](T-100.md), FinancialEligibility and SourceCurrency. Exact-reference
evidence permits a preview only. Persisted links require accepted accounting,
transactional constraints, durable Undo and archive/delete coverage. Canonical
calendar totals wait for the owner period choice. Card consumers must reuse
this contract rather than introduce another refund interpretation.
