## T-171a — Cross-reference only (do not duplicate T-210)

T-171a ("CI shards for Flutter unit/widget, Android unit, migration, and
fixture-contract tests with deterministic failure artifacts") is implemented
*after* T-210 provides:

- `tool/ci/shard_tests.py` and `tool/ci/test_durations.json` (T-210f) for
  duration-balanced Flutter shards with a no-file-lost `--check`;
- `dart_test.yaml` tags `migration`/`slow`/`perf` (T-210a, T-210g1/g2) so a
  dedicated migration job (`flutter test --tags migration`) is possible while
  the Flutter shards still run *every* test;
- `tool/ci/test_durations.py` (T-210a) and the JSON event files used as
  failure artifacts.

T-171a owns `.github/workflows/ci.yml`. It must keep analyze, build_runner
staleness and manifest-scope checks as single required jobs, add the shard
matrix (`K` from T-210h), an Android unit job (`./gradlew :app:testDebugUnitTest
:paisatrack_keystore:testDebugUnitTest`, `docs/development.md:49-51`), and
a fixture-contract job (`test/fixtures/sms`, `test/ci`). Budget gates below
(T-171b3) are added to the release-candidate workflow, not to PR CI.

## T-171b — Performance and accessibility acceptance budgets

Goal: publish the budgets as docs, make them machine-checkable, and gate
release candidates on *measured evidence*. Missing evidence fails the gate
(R-20: no conflation of device gates, `docs/plans/risk-register.md`). Budgets
start as "proposed, to calibrate"; they become binding only after the first
owner-device calibration run (T-115/T-165a) records a baseline and the owner
accepts the numbers.

Parallel groups: A = b1, b2a; B = b2b, b2c, b3; C = b4.

## T-171b2a — Accessibility guideline test harness   (~M ; suggested model: Sonnet)
- Depends: —   Parallel group: A
- Owns: `test/support/a11y_guidelines.dart` (new),
  `test/accessibility/a11y_harness_test.dart` (new)
- Reads: `test/support/bloom_test_helpers.dart`,
  `test/features/shell/global_bottom_inset_acceptance_test.dart` (viewport
  setup), Flutter `meetsGuideline` API (`androidTapTargetGuideline`,
  `labeledTapTargetGuideline`, `textContrastGuideline`).
- Do:
  1. `Future<A11yFinding> auditScreen(WidgetTester, {required Widget app,
     required A11yConfig config})` that pumps the screen under: viewports
     360x640, 411x891 and landscape 891x411; text scale 1.0, 1.3, 2.0; light
     and dark; with `tester.ensureSemantics()`; runs the three guidelines plus
     a custom check that every `Semantics` button has a non-empty label and a
     >= 48x48 hit area; returns findings with widget path.
  2. `expectNoNewViolations(findings, ratchet: const {...})`: fails when a
     finding is *not* in the ratchet list **and** fails when a ratchet entry
     no longer occurs (forces list shrinkage). Each ratchet entry carries the
     T-167x task that will fix it. This is a strict ratchet, not a skip.
  3. Harness self-test using a deliberately bad 20x20 unlabeled button and a
     low-contrast text fixture: both must be detected (non-vacuous).
- Acceptance: harness test proves detection of 3 violation kinds and the
  ratchet's two failure directions.
- Checks: `flutter analyze --no-pub`; `flutter test test/accessibility`.
- Privacy/rollback: test-only.

## T-171b3 — Machine-readable budgets and release-evidence checker   (~M ; suggested model: Sonnet)
- Depends: T-171b1, T-208l   Parallel group: B
- Owns: `tool/perf/budgets.json` (new), `tool/perf/check_budgets.py` (new),
  `tool/perf/check_budgets_test.py` (new)
- Reads: `docs/acceptance-budgets.md` once b1 lands,
  `tool/perf/bootstrap_ci.py` output format (T-208l), host perf JSON
  (T-208d/e), frame summary JSON (T-208j2).
- Do:
  1. `budgets.json`: `{id, metric, comparator, value, unit, source}` for each
     budget, with `status: proposed|calibrated`.
  2. `check_budgets.py --evidence dir --release-candidate sha`: loads evidence
     files, prints a table, and exits non-zero when a *calibrated* budget is
     exceeded, a required evidence file is missing, the evidence names a
     different commit/APK hash, or the sample count < 30. `proposed` budgets
     print as `ADVISORY` and never fail (so the gate cannot block on an
     uncalibrated guess) but missing evidence for them is listed.
  3. Never substitute one device's evidence for another gate (R-20): evidence
     files carry `gate` and `device` fields; mismatches fail.
- Acceptance: unit tests for pass, exceed, missing, wrong SHA, too few samples,
  advisory-only cases.
- Checks: `python3 -m unittest tool/perf/check_budgets_test.py`.
- Privacy/rollback: reads numbers only.
