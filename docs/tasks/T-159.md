# T-159 — Regression coverage for transaction correction and detail rendering

`transaction_detail_screen_test.dart` is seven-eighths render/geometry
assertions; no test exercises the category-correction, undo, or
exclusion-classification paths T-157/T-158 are about to move. Build the safety
net first (T-159a), then expand coverage after extraction (T-159b/c).

### T-159a — Characterize category-correction and undo behavior before extraction   [P1] [~M]
Files:    `test/features/transactions/transaction_detail_screen_test.dart`,
          `test/features/review/weekly_review_screen_test.dart` (create if
          absent), `lib/data/repositories/transaction_repository.dart:321`
          (`updateWithFeedback`), `:569` (`correctCategory`)
Depends:  none — land before T-157b starts
Change:   Add behavioral tests exercising `_changeCategory` and
          `_selectCategoryDirectly` end-to-end against an in-memory DB: tap a
          category chip → assert `transaction_repository.correctCategory` was
          called with the expected arguments (or, if not cleanly mockable,
          assert the DB row's category actually changed) → assert an undo
          token was pushed → trigger undo → assert the DB row reverted. Mirror
          the same shape for `weekly_review_screen`'s `_confirmItem`/
          `_recategorizeItem`.
Tests:    This task's deliverable is the tests themselves.
AC:       At least one test per extraction target (`_changeCategory`,
          `_selectCategoryDirectly`, `_confirmItem`, `_recategorizeItem`) fails
          if the underlying repository call or undo-token push is removed or
          reordered.
Rationale: T-157b is the highest-risk extraction in this plan and currently
          has zero behavioral coverage for the undo path.
