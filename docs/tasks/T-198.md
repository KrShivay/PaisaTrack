# T-198 — Readable payee names for VPA-only rows and 'Unknown' merchants

## Owner-phone evidence (2026-10-02/03)

- Activity, Sort and detail titles show raw VPAs such as
  `zomato.eternaltsp.payu@hdfcbank`, `payzomato@hdfcbank`, `paytm.s22rtcb@pty`.
- Trends "Top merchants" lists several separate "Unknown" rows (e.g. the
  personal-loan and SIP debits) and phone-number VPAs.

## Scope

A display-name layer (no identity merge, no writes) that prefers the user
label, then the merchant canonical name, then a readable brand derived with
the R4 `PayeeKey.brandTokens` rules (e.g. "Zomato"), then the SMS payee text,
and only then the VPA; opaque gateway ids and phone VPAs stay as-is or show a
neutral label ("UPI payee") with the VPA visible in T-196's details card.
"Unknown" merchant rows in Top merchants get a meaningful label (category or
SMS sender) and are not split into several identical "Unknown" lines.
Respect PLAN.md: no silent merges; suggestions only.

## Acceptance

Unit tests on the owner examples; widget tests for Activity/Top merchants;
physical check. Depends on T-177 R4 (done, `8e4eb65`).
