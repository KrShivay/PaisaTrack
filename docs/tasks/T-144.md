# T-144 — Play declaration and consent

P1 despite sitting last: the declaration text must describe the admission
behaviour T-133 ships, so it cannot be written earlier — but it gates
distribution (T-094) and should not be discovered late.

PaisaTrack qualifies under a **named Play exception**: "SMS-based money
management — For example, apps that track and manage budget", covering
`READ_SMS`, `RECEIVE_MMS`, `RECEIVE_SMS`, `RECEIVE_WAP_PUSH`. Grants are
case-by-case via the Permissions Declaration Form.

### T-144a — Manifest scope and CI guard   [P1] [~S]
Files:    `android/app/src/main/AndroidManifest.xml`, CI workflow
Depends:  none
Change:   The exception does **not** cover `SEND_SMS` or `WRITE_SMS`. Ensure
          neither is declared, and add a merged-manifest CI check that fails the
          build if either appears — including transitively from a dependency.
          Keep the existing inline justification for `INTERNET`
          (model download only).
Tests:    CI check fails on a manifest with `SEND_SMS` injected.
AC:       The manifest declares no SMS permission outside the exception list, and
          regression is mechanically prevented.

### T-144b — Disclosure and capture controls   [P1] [~M]
Files:    `lib/features/onboarding/onboarding_screen.dart`,
          `lib/features/settings/settings_screen.dart`, `docs/privacy.md`
Depends:  T-133a (final admission behaviour)
Change:   Prominent in-app disclosure **before** the runtime prompt, in plain
          words: what is read, that it stays on the device, what happens on
          decline. Add per-sender and global capture pause with immediate,
          visible effect. Update `docs/privacy.md` to describe shape-based
          triage accurately rather than implying a fixed bank allowlist —
          T-133a changes what the app reads before rejecting.
Tests:    Disclosure precedes the prompt and survives denial (T-113's
          continue-without-SMS path still works). Pausing capture stops ingestion
          immediately.
AC:       Store listing headlines SMS budget tracking as core functionality; the
          sideload path (T-094) remains viable if the declaration is refused.
Rationale: `docs/sms-intelligence-design.md` §11.
