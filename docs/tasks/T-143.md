### T-143b — Link and adversarial fixtures   [P1] [~M]
Files:    `test/fixtures/sms/` (new sequence shape),
          `test/support/fixture_loader.dart`
Depends:  none
Change:   Add two fixture shapes. **Sequences**: ordered multi-message cases with
          an expected event graph — auth→settle, debit→reversal, expense→refund,
          reminder→fulfilment, bank+wallet echo. This is the only honest way to
          test L5/L6. **Adversarial**: extraction bait where a plausible-but-
          absent amount is the tempting answer. ADR 0005 provenance rules apply
          unchanged — `public` or sanitized `device` only.
Tests:    The loader reads both shapes; existing single-message fixtures are
          unaffected.
AC:       T-131c, T-134b, and T-138c have fixtures to assert against.

### T-143c — Shadow mode and the metrics surface   [P1] [~L]
Files:    `lib/features/dev/`, `lib/capture/shadow_pipeline.dart` (new)
Depends:  T-143a, T-143b
Change:   Run the new pipeline beside the current one, write to a shadow table,
          and report the diff — records gained, records lost, amount deltas,
          label disagreements. Compute the design §13.2 metric set on-device.
          Nothing leaves the device except by explicit user export.
Tests:    Shadow writes never touch production rows; the diff is empty when both
          pipelines are identical.
AC:       No stage of the rework is promoted until shadow reports zero lost
          transactions on a real inbox.
Note:     This sub-task is `~L`. Split it further before claiming it — a
          reasonable cut is (i) shadow table + runner, (ii) diff computation,
          (iii) dev-screen presentation.
Rationale: `docs/sms-intelligence-design.md` §13.
