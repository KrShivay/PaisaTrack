# T-156 — Sheet and dialog presentation consolidation

`showBloomModalSheet` and `showBloomFullScreenSheet` (shipped under T-152a)
already give the app two consistent sheet primitives. Sixteen dialogs and four
bespoke sheet-presenter functions still bypass both, and `TransactionDetailScreen`
itself is opened three inconsistent ways.

### T-156a — Wrap raw AlertDialog/showDialog sites in a shared Bloom dialog helper   [P2] [~M]
Files:    `lib/features/settings/settings_screen.dart:404,521,924`,
          `lib/features/settings/payment_sources_screen.dart:120,151`,
          `lib/features/settings/category_manager_screen.dart:260,275`,
          `lib/features/settings/payee_labels_screen.dart:175,242,260,301,330`,
          `lib/features/recovery/key_loss_screen.dart:18`,
          `lib/features/dashboard/dashboard_widgets.dart:570`,
          `lib/features/sms/unparsed_sms_screen.dart:87,173`,
          new `lib/core/widgets/bloom/bloom_dialog.dart`
Depends:  none
Change:   Add a `showBloomDialog` helper (Bloom-styled `AlertDialog`: shared
          corner radius, action-button styling, scrim) mirroring
          `showBloomModalSheet`'s role for sheets. Migrate all 16 raw
          `showDialog`/`AlertDialog` call sites to it, preserving each dialog's
          existing copy, actions, and dismissal exactly — chrome-only change.
Tests:    A widget test per migrated screen asserting the dialog still contains
          its original title/body/action text and each action still triggers
          its original callback.
AC:       Zero raw `showDialog(` calls remain outside `bloom_dialog.dart`; no
          dialog's action behavior changed.
Rationale: audit found 16 dialog call sites with no shared styling helper,
          unlike sheets which already have two.

### T-156b — Route bespoke sheet presenters through the Bloom helpers   [P2] [~M]
Files:    `lib/core/widgets/transaction_filter_sheet.dart:174-188`,
          `lib/core/widgets/correction_scope_sheet.dart:6-27`,
          `lib/features/transactions/transaction_source_actions.dart:65-79`,
          `lib/features/settings/category_manager_screen.dart:304-320` (`_askCategory`)
Depends:  none
Change:   Replace each function's independent `showModalBottomSheet(...)` call
          with `showBloomModalSheet` (or `showBloomFullScreenSheet` for
          `_askCategory`, matching the other three category-editor flows
          already migrated under T-145a) so drag handle, scrim, and safe-area
          handling come from one place instead of four. Preserve each sheet's
          content, return value, and dismissal semantics exactly.
Tests:    Existing tests for `transaction_filter_sheet`, `correction_scope_sheet`,
          and category_manager_screen's category dialog pass unchanged; add a
          widget test asserting all four now render the shared Bloom handle.
AC:       None of the four functions calls `showModalBottomSheet` directly.
Rationale: `category_manager_screen.dart:304-320` is a fourth, inconsistent
          category-editor sheet style alongside the three already migrated.

### T-156c — Standardize TransactionDetailScreen's presentation   [P2] [~M]
Files:    `lib/features/transactions/transactions_screen.dart:120-127`,
          `lib/features/dashboard/dashboard_screen.dart:220-224`
Depends:  T-158c (land the screen split first so this doesn't entangle with
          the widget-extraction diff)
Change:   `TransactionDetailScreen` opens three inconsistent ways today —
          `showBloomModalSheet` + `FractionallySizedBox(heightFactor: 0.9)`
          from `transactions_screen.dart`, and `showBloomModalSheet` with
          default sizing from `dashboard_screen.dart` — despite owning its own
          internal `Scaffold`+`AppBar`. Pick one presentation (full-screen
          sheet, consistent with T-151a's direction for other full screens
          crammed into partial sheets) and use it from both call sites.
Tests:    Widget test asserting both entry points produce the same sheet
          height/chrome.
AC:       `TransactionDetailScreen` renders identically regardless of entry
          point.
Rationale: audit found the same screen rendered at two different heights
          depending on which screen opened it, with no shared presentation
          call between them.
