# T-156 — Sheet and dialog presentation consolidation

`showBloomModalSheet` and `showBloomFullScreenSheet` (shipped under T-152a)
already give the app two consistent sheet primitives. Sixteen dialogs and four
bespoke sheet-presenter functions still bypass both, and `TransactionDetailScreen`
itself is opened three inconsistent ways.

### T-156a — Wrap raw AlertDialog/showDialog sites in a shared Bloom dialog helper   [P2] [~M]
Files:    `lib/features/settings/settings_screen.dart:404,521,924`,
          `lib/features/settings/payment_sources_screen.dart:120,151`,
          `lib/features/settings/category_manager_screen.dart:260,275`,
          `lib/features/settings/payee_labels_screen.dart:175,242,260,301,330`,
          `lib/features/recovery/key_loss_screen.dart:18`,
          `lib/features/dashboard/dashboard_widgets.dart:570`,
          `lib/features/sms/unparsed_sms_screen.dart:87,173`,
          new `lib/core/widgets/bloom/bloom_dialog.dart`
Depends:  none
Change:   Add a `showBloomDialog` helper (Bloom-styled `AlertDialog`: shared
          corner radius, action-button styling, scrim) mirroring
          `showBloomModalSheet`'s role for sheets. Migrate all 16 raw
          `showDialog`/`AlertDialog` call sites to it, preserving each dialog's
          existing copy, actions, and dismissal exactly — chrome-only change.
Tests:    A widget test per migrated screen asserting the dialog still contains
          its original title/body/action text and each action still triggers
          its original callback.
AC:       Zero raw `showDialog(` calls remain outside `bloom_dialog.dart`; no
          dialog's action behavior changed.
Rationale: audit found 16 dialog call sites with no shared styling helper,
          unlike sheets which already have two.

### T-156c — Standardize TransactionDetailScreen's presentation   [P2] [~M]

          the widget-extraction diff)

          from `transactions_screen.dart`, and `showBloomModalSheet` with
