# T-203 — Import flicker and speed (P0, Ready)

Status: Proposed brief, planning only — 2026-10-10. Plan and budgets:
[performance plan](../plans/performance.md). Benchmarks come from
[T-208](T-208.md) (T-208e). The earlier worker branch `wt-flicker` never
reached the remote; assume nothing landed.

Owner symptom: on a fresh install with a large inbox, lists vanish and
reappear and screens flicker while history import runs.

## Root causes found (evidence)

1. **Dependency-driven reload shows skeletons.** Riverpod is 2.6.1
   (`pubspec.lock`). `AsyncValue.when` defaults to `skipLoadingOnReload:
   false`; a provider that is rebuilt because a watched dependency changed is
   `AsyncLoading` with the old value, so `.when(loading:)` renders the
   skeleton. 37 `.when(` call sites exist in `lib/` (38 grep lines, one is a
   comment at `lib/data/repositories/feature_flag_repository.dart:407`).
   - 18 are UI sites that render a loading placeholder (listed per subtask).
   - 19 are provider-level `databaseAsync.when(data: stream, loading: empty,
     error: Stream.error)` gates that are copy-pasted (DRY violation).
2. **Dashboard reloads on every list emission.**
   `dashboardAggregateProvider` does `ref.watch(transactionListProvider)`
   (`lib/features/dashboard/dashboard_providers.dart:240`). Every Drift
   emission of the 100-row list rebuilds the aggregate (6 SQL queries,
   `lib/data/repositories/dashboard_repository.dart:113-124`). The hero tile
   uses `.when(loading: skeleton "Updating…")` and an `AnimatedSwitcher` whose
   key contains `contentAsync.runtimeType`
   (`lib/features/dashboard/dashboard_widgets.dart:195-198`), so each reload
   is a visible skeleton cross-fade. Every dashboard card derived through
   `whenData` inherits the loading state.
3. **Many consumers re-query per page commit.** `ingestBatch` already wraps a
   200-message page in one outer transaction (`lib/capture/sms_ingestion.dart:
   617-621`, page size `lib/core/constants.dart:67`), so Drift emits about one
   notification per page, but each notification re-runs every watched query
   (transaction list, Dashboard recents, review queue, Activity pages,
   insights) and decodes rows on the UI isolate. Nothing throttles that.
4. **Activity freezes silently.** `ActivityTransactionPageController` ignores
   a live update that changes page membership
   (`lib/features/transactions/transactions_providers.dart:128-135`), so
   during import Activity looks stuck until the user reopens it. The screen
   keeps data on reload (`valueOrNull`, `transactions_screen.dart:226-228`) but
   gives no signal that newer rows exist. Day-group sections have no key
   (`_groupedItem`, `transactions_screen.dart:540,622`); rows do
   (`ValueKey(item.id)`, `:1001`).
5. **Derived reads are already suspended during import** (`SmsHistoryImporter`
   and `SmsIncrementalCatchUp` wrap `_run` in `withInvalidationSuspended`,
   `lib/capture/sms_backfill.dart:377,527`), so the end-of-import burst is the
   problem: one trailing `invalidate()` then a pure debounce
   (`derived_reads_service.dart:88-106`, 1.5 s). A pure debounce can starve
   under continuous writes outside suspension, and the rebuild writes
   insights/recurring tables, which fires another wave of stream emissions at
   the moment the import finishes.
6. **No import progress outside onboarding.** `smsBackfillStatusProvider` is
   consumed only by onboarding (`onboarding_screen.dart:20`); `total` is never
   set and `transactionsFound` is not forwarded
   (`sms_backfill.dart:825-829`). Home has no banner.

## Design (summary)

- `whenStable` extension: `when` with `skipLoadingOnReload` and
  `skipLoadingOnRefresh` true. Loading only renders when there is no value.
- `DatabaseGate.watchWith` extension replaces the 19 provider-level gates.
- `throttleLatest` stream operator (leading edge immediate, one event per
  window, trailing edge always delivered, flush on done) gated by
  `smsImportActiveProvider`, applied to list/review/recents streams only
  while import runs. Totals are never throttled to a stale value: the trailing
  edge always carries the newest event.
- Dashboard aggregate refreshes through a throttled change tick and keeps its
  previous value while refreshing.
- Derived reads gain `maxWait` (no starvation) and keep the guaranteed
  trailing run.
- Activity shows "N new transactions" pill when membership changes are
  withheld; tapping refreshes the first page.
- Global import progress banner in `HomeShell`.

- Do:
  1. `Stream<T> throttleLatest<T>(Stream<T> source, Duration window,
     {bool Function()? enabled})`: when `enabled?.call() ?? true`, deliver the
     first event immediately, then at most one event per `window`, always

     `ref.watch(smsBackfillStatusProvider.select((s) => s.stage ==

  - 100 events in 1 s with 400 ms window emit <= 4 events and the LAST event
    value is always delivered (trailing edge).
  - Source `done` flushes a pending event before closing.
  - `enabled == false` emits all 100 events untouched.
  - Cancel leaves no pending timers.
  - Provider flips true only while stage is `running`.
- Checks: `flutter analyze --no-pub`; `flutter test test/core/async`.
- Privacy/rollback: content-free; unused until adopted, revert file.
