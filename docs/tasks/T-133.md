# T-133 — Admission and quarantine

27 allowlisted sender tokens hard-drop everything else in Kotlin with only
in-memory counters, so an unlisted bank silently under-reports spending while the
app looks complete.

### T-133a — Shape scoring and quarantine store   [P1] [~L]
Files:    `android/app/src/main/kotlin/com/paisatrack/capture/SmsFilter.kt`,
          `lib/data/db/tables/raw_sms_table.dart`, `lib/capture/sms_ingestion.dart`
Depends:  T-129 reason codes, T-132b message kinds
Change:   Sender identity becomes a **confidence prior, not a gate**. Score shape:
          currency token +2, settled/pending/failed verb +2, account/card/VPA
          token +1, reference/UTR token +1. Reject OTP shape without a settled
          verb; reject numeric senders below score 5 (personal messages);
          admit ≥4; **quarantine 2–3** with `admission='quarantined'`; reject
          below 2 with a durable content-free reason code. Non-matching bodies
          are never persisted.
Tests:    JVM unit tests on the scorer. A transaction-shaped message from an
          unlisted sender is quarantined, not dropped. No test asserts on a body.
AC:       No transaction-shaped message is discarded without a durable counted
          reason. Quarantined bodies obey the existing 30-day retention.
Note:     `~L`. Split as (i) Kotlin scorer + tests, (ii) quarantine persistence,
          (iii) retry-version plumbing.
