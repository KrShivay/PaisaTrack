### T-154b — Inline corrections and guess refresh   [P2] [~M]
Files:    `lib/features/review/weekly_review_screen.dart`,
          `lib/enrichment/categorizer.dart` (read path only)
Depends:  T-154a
Change:   (1) Add a "Not right?" affordance on the card for the frequent cases —
          wrong merchant, wrong amount, not a spend (transfer/refund),
          duplicate — so they do not need a full detail round trip. (2) **Refresh
          the classifier suggestion after any edit before Keep is enabled.**
          Confirming a category writes feedback, rules, and learned aliases in
          one transaction, so accepting a guess derived from a corrected-away
          merchant teaches the wrong rule and propagates it to future messages.
Tests:    Editing the merchant recomputes the guess and disables Keep until it
          settles. Assert no rule is written from a stale guess.
AC:       No learned rule can originate from a guess computed against a merchant
          string the user has since corrected.
Rationale: `docs/ui-gaps-and-redesign.md` §U10.
