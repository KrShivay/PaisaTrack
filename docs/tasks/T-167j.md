# T-167j — App-wide back navigation

**Status:** In Review
**Priority:** P0

## Problem

The Bloom shell owns four nested tab Navigators, but its current `PopScope`
force-pops the active Navigator and can pop an enclosing route. It has no
deliberate Home exit confirmation, while lazily built pages may discard an
inactive tab's route history. System back, Android predictive back, and visible
in-app back controls therefore lack one tested contract.

## Contract

- A root modal or transient route closes before the shell handles back. Android
  consumes a visible software keyboard's back action before Flutter; text focus
  alone does not count as a visible keyboard or consume shell back.
- Otherwise, back asks the active tab Navigator to `maybePop`, preserving route
  vetoes and confirmation callbacks. Every tab Navigator and its visited stack
  remains alive while switching tabs or swiping between pages.
- At a tab root, Activity, Sort, or Trends returns to Home. Home-root back
  announces “Press back again to exit” in a live region and starts a two-second
  confirmation window. A second deliberate back inside that window exits via
  `SystemNavigator.pop`; expiry, route/transient changes, tab changes, and app
  backgrounding clear the pending confirmation. It never pops a parent route
  such as onboarding or a permission screen.
- Re-selecting the current tab retains its existing behavior: pop that tab to
  its root. PageView swipe navigation remains supported.
- Android predictive transitions are registered only for the active tab while
  the shell is uncovered. Cancel leaves all tab stacks and any armed Home exit
  unchanged; commit pops one active nested route. A root dialog without a
  predictive route transition closes through Flutter's normal committed-back
  path and leaves every nested stack intact. Custom Android builders and all
  non-Android transition builders are preserved. See [ADR 0022](../decisions/0022-scoped-predictive-back.md).
- Retained inactive and root-covered tab stacks have tickers disabled. Their
  bounded four-tab route state remains alive and resumes when selected.
- Programmatic tab requests and user tab/swipe selection share one provider
  state. Returning Home must not leave a stale Activity selection that prevents
  a later identical request from navigating again.

## Acceptance

- Widget tests cover nested route `maybePop`/veto and one-at-a-time history,
  persistent stacks across nonadjacent tab switches, tab-root Home fallback,
  all non-Home roots, same-tab reselection, programmatic tab requests, swipe
  retention, root sheet precedence, Home exit prompt/accessibility, timeout
  expiry, async-veto overlap, IME visibility and lifecycle reset, and clearing
  the armed state when a root sheet is opened and dismissed before timeout.
- Android widget-channel tests verify canceled predictive gestures preserve the
  active stack and Home exit arm, committed gestures pop exactly one active
  route, inactive stacks do not pop, custom transition builders are retained,
  and a root dialog closes without changing nested stacks.
- Test seams are private or supplied by Flutter test bindings; no public
  production-only testing API is added. Fake time verifies the two-second
  boundary, and a platform-channel interceptor verifies the exit call without
  terminating the test process.
- Android API 36 device QA on the isolated recovery-QA package verifies
  software-IME back precedence, system-button/edge-gesture parity, committed
  and canceled predictive-back gestures, and that no onboarding/permission
  route is exposed. Do not install over the owner's production package or
  inspect private SMS/database data.
- Run focused tests, touched test directories under `America/New_York`, the full
  Flutter suite, `flutter analyze`, formatter, documentation-link and diff
  checks, plus complete GitNexus `detect-changes` before review. Parent performs
  independent code review before a coherent commit.

## Scope and follow-ups

Keep the existing nested Navigator/PageView design and public navigation
surfaces. No database, SMS, permission, release-signing, or `T-194` branch
changes. Physical IME and predictive-gesture evidence remains a device gate and
must be reported separately from host widget results.

## Regression and host verification

Before implementation, the focused back-navigation regression cases were red
(0/4): route veto was bypassed, a visited tab stack was lost, and Home had no
two-step exit prompt. The root-sheet reset test could not reach its assertion
because the first Home prompt was missing.
The expanded focused suite passes 17/17, including Android channel-driven
predictive commit and cancellation. A four-tab retained shell bounds inactive
Navigator roots to four; inactive/covered tickers are disabled to avoid
background animation work. There is no cap on route depth within a visited tab.
These host results do not close the API 36 device gate above.

Host verification: focused T-167j tests 17/17; shell and home test directories
under `America/New_York` 60/60; full Flutter suite 1,246/1,246; `flutter analyze`
reports no issues; Dart formatting, 140-file Markdown link checks, and
`git diff --check` pass. The encrypted database migration test ran in the full
suite. Native Android IME and predictive gesture checks remain unverified.
