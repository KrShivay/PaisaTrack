# T-098 — Per-category monthly budgets

Status: Proposed, refreshed 2026-10-10. The existing global prototype is not
this feature. Board name "budgets" = per-category monthly budgets (this brief).

Dependencies (refreshed): [T-165c](T-165c.md) integer minor units (limits,
remaining and thresholds compare exact integers; budget limit columns are born
integer, never REAL) and [T-100c1](T-100.md) canonical net spend with the
single `RefundAttribution` switch (T-209). A budget under purchase-period
attribution can be restated by a late refund; under posting-period it cannot.
Budget code reads `NetSpend` only and never decides attribution.

## Current state and real gaps

- `BudgetRepository` stores one global monthly amount and merchant caps as
  `baselines` rows keyed by `monthly_budget` or `cap_*`
  ([source](../../lib/data/repositories/budget_repository.dart#L7)); it does
  not model category/month budgets.
- `FinancialEligibility.spendingDebit` is the shared settled, non-excluded,
  non-transfer debit predicate ([source](../../lib/data/analytics/financial_eligibility.dart#L26)).
- `FinancialEvents.netAmountPaise` exists, but current consumers and refund
  semantics were not established. T-100 must define net spend before budgets
  consume it.
- Gap: category/month limits, currency handling, period calendar, explanation
  of exclusions, threshold/remaining/projection, migration away from prototype,
  and budget archive/reset coverage.

## Scope and non-goals

Create optional per-category/per-month budgets with clear remaining and
threshold status based on canonical net spending. No automatic rollover,
cross-currency conversion, mandatory category creation, or use of forecast
estimates as settled actuals.
