# T-153 — Sort cursor and recoverable skip

`_currentIndex` is `final int = 0`, so the deck always renders `activeItems[0]`.
Advancing is a side effect of skip filtering the item out. There is no cursor, so
"previous" is unrepresentable — not merely unimplemented.

### T-153a — Replace the filter with an ordered queue and cursor   [P2] [~M]
Files:    `lib/features/review/weekly_review_screen.dart:29-33,51-74,239-247`
Depends:  none
Change:   Hold one stable ordered `List<TransactionReviewItem>` for the session
          plus a mutable `int _cursor`. Skip advances the cursor and marks the
          item `skipped`; it no longer removes it from the list. Resolved items
          (confirmed or recategorised) are removed. Delete the
          `items.where((i) => !_skippedIds.contains(i.id))` filter at line 53 and
          make `_currentIndex` a mutable `_cursor`.
Tests:    Test at a **non-zero cursor** — the existing `clamp` and `_dragDx`
          paths are dead code today and untested. Assert skip advances without
          removing; assert resolve removes.
AC:       The rendered card is a function of the cursor, not of list mutation.
Impact:   Run `impact({target: "WeeklyReviewScreen", direction: "upstream"})`.

### T-153b — Back navigation   [P2] [~S]
Files:    `lib/features/review/weekly_review_screen.dart:192-228`
Depends:  T-153a
Change:   Add a previous control and a swipe-right-to-go-back gesture moving the
          cursor backwards through everything already seen, skipped or resolved.
          A mis-swipe becomes one gesture to recover, consistent with the 10s
          undo used for other destructive actions.
Tests:    Widget test: skip then back returns the same card; back at cursor 0 is
          a no-op, not a crash.
AC:       Any card seen this session can be returned to in one gesture.

### T-153c — End state, persistence, and progress   [P2] [~M]
Files:    `lib/features/review/weekly_review_screen.dart`,
          `lib/features/review/weekly_review_providers.dart`
Depends:  T-153a
Change:   (1) When the cursor reaches the end with skipped items remaining, show
          "N skipped — review them?" instead of `_InboxZeroView`; Inbox Zero must
          mean resolved, not dismissed. Today skipping everything shows the
          celebration. (2) Move skip state out of widget state into the review
          provider so it survives process death mid-sort. (3) Extend the segment
          progress bar to distinguish position, resolved, and skipped rather than
          only counting down.
Tests:    Skip-all shows the skipped prompt, not Inbox Zero. Skip state survives
          a provider rebuild. Progress bar reflects three states.
AC:       Inbox Zero appears only when nothing is unresolved or skipped.
Rationale: `docs/ui-gaps-and-redesign.md` §U9.
