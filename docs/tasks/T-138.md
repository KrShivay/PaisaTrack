# T-138 — Expected events

Closes T-101. Bill-due and autopay messages are currently discarded, so a first
bill is invisible until paid and a missed payment cannot be detected.

**Invariant:** expected events are never transactions and never enter any
spending aggregate.

### T-138a — Schema   [P2] [~M]
Files:    `lib/data/db/tables/expected_events_table.dart` (new)
Depends:  T-132a
Change:   (id, source, origin_sms_id, series_id, counterparty_id, label,
          expected_amount paise, amount_low, amount_high, expected_date,
          date_window_days default 3, cadence, state ∈ expected|fulfilled|
          missed|cancelled|snoozed, fulfilled_txn_id, confidence, dedup_key).
          Unique index on (dedup_key, expected_date) — this is what collapses
          repeated reminders for one obligation.
Tests:    Migration; the unique index rejects a duplicate reminder.
AC:       Additive; no spending query references this table.

### T-138b — Reminders and mandates become expected events   [P2] [~M]
Files:    `lib/capture/sms_ingestion.dart`, expected-event repository
Depends:  T-138a, T-132c
Change:   Route `reminder` and `mandate` kinds here instead of dropping them.
          Amount ranges when the message gives a range rather than a figure.
          `dedup_key` derives from counterparty + cadence + rough amount so three
          reminders for one bill produce one event.
Tests:    Three reminders for the same bill produce one event. A reminder never
          creates a transaction.
AC:       Reminder deduplication ≥0.95.

### T-138c — Fulfilment, snooze, cancel, missed   [P2] [~M]
Files:    expected-event repository, `lib/features/recurring/`
Depends:  T-138b, T-134b, T-143b sequence fixtures
Change:   Match a later debit at ≥0.85 into `fulfilled`, preserving both the
          expectation and the transaction. Past the date window with no match →
          `missed`. Support snooze and cancel.
Tests:    Sequence fixture: reminder → debit → fulfilled. Reminder with no debit
          → missed. Both rows remain visible.
AC:       A missed payment is detectable, which is impossible today because
          nothing is ever expected.
Rationale: `docs/sms-intelligence-design.md` §6.4.
