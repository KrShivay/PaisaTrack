# T-190a1 — Read-only card source audit

Status: Host complete; independently reviewed and accepted on 2026-10-04. Card accounting and
ownership mutation remain proposed in [T-190](T-190.md) and
[ADR 0020](../decisions/0020-credit-card-accounting.md).
Contract: [ADR 0027](../decisions/0027-read-only-card-source-audit.md).

## Visible outcome

Open a separate "Card source audit" route from Settings. Show stored payment
sources, masked identifiers, recorded institution/nickname or explicit absence,
transaction counts, source-currency/lifecycle groups, and bounded pages of
possible card transactions. Card channel and stored/inferred owned flags never
mean a confirmed credit-card product or confirmed ownership. Missing or
conflicting evidence remains visible for review.

## Read-only boundary and query design

- Use a direct read-only repository/provider. Do not mount PaymentSourcesScreen
  or paymentSourcesProvider: its initial load runs transfer reconciliation.
- Aggregate history in SQL; never materialize all transaction rows. Bound and
  paginate candidate rows deterministically by timestamp and ID, preserve
  unknown source-currency buckets, and expose partial report coverage.
- Report conflicts only when stored account-hint/channel evidence maps to
  multiple source IDs or recorded institution labels. A historical collision
  already collapsed into one source cannot be reconstructed from current
  storage; do not invent an issuer or claim no collision exists.
- No raw-SMS reads, source edits, ownership/product confirmation, transaction
  changes, transfer reconciliation, refund links, liability or balance totals.
- Reuse T-100's refund review/accounting contract in later card phases rather
  than creating a parallel refund projection. This source audit uses neither
  calendar netting nor the new preparation API to classify card refunds.

## Acceptance and verification

- Synthetic bank/card/wallet/unknown sources, absent labels, duplicate hint
  evidence, observable conflicts and unobservable historic collisions.
- SQL group counts and currency/lifecycle buckets, deterministic pagination,
  missing sources and excluded/deleted/duplicate source facts stay truthful.
- Seed sources, transactions, links and feedback; read report and real Settings
  route, then prove all values and financial aggregates unchanged. A fixture
  that could reconcile transfers must still retain its original state.
- Widget/provider tests exercise loading/error/retry/empty state, route access,
  unverified wording and compact/large-text layout. Meaningful labels and
  48dp action targets, scrollable final content and no privacy-sensitive errors.
- Run focused tests, America/New_York focused tests, full serial Flutter suite
  with encrypted migration, analyzer, changed-file formatter, documentation
  links, diff checks, independent Sol review and complete refreshed GitNexus
  change scans before commit. No schema or archive changes.
