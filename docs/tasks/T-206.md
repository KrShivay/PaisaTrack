## Merge to `main` (owner/orchestrator)

PR #153 already exists. The session proxy cannot merge-and-delete, so the
owner (admin on `KrShivay/PaisaTrack`) or an orchestrator with a normal token
does this:

1. **Freeze the integration head.** Stop pushing to
   `claude/paisatrack-multi-feature-mh2nhw`; record the SHA:
   `git ls-remote origin refs/heads/claude/paisatrack-multi-feature-mh2nhw`.
2. **Wait for green CI on that exact SHA.** The suite is slow (~15 min,
   T-210). Check the PR "Checks" tab or
   `gh api repos/KrShivay/PaisaTrack/actions/runs?branch=claude/paisatrack-multi-feature-mh2nhw`.
   If CI is red, fix on the integration branch and return to step 1.
3. **Merge with a merge commit, not squash.** History, ADR/TASKS references
   and the 33 per-task commits stay intact, and the integration branch tip
   becomes an ancestor of `main` (so "fully merged" checks work).
   - GitHub UI: PR #153 -> **Create a merge commit**; or
   - CLI: `gh pr merge 153 --merge` ; or REST:
     `gh api -X PUT repos/KrShivay/PaisaTrack/pulls/153/merge -f merge_method=merge`
     (use a normal token; the session proxy blocks GraphQL and branch deletion).
   Do **not** tick "Delete branch" yet if step 5 is still pending.
4. **Verify.** `git fetch origin && git merge-base --is-ancestor
   origin/claude/paisatrack-multi-feature-mh2nhw origin/main && echo merged`;
   then confirm the push-to-`main` CI run passes.
5. **Update local clones.** `git checkout main && git pull --ff-only`
   (local `main` in this checkout is behind `origin/main`).
6. Record in `WORKLOG.md`/`TASKS.md` (orchestrator): merge SHA, date, the
   deleted-branch list, and move T-206 to Done when the checklist below is
   complete.

## Constraints and invariants

- Never force-push `main`; never delete the integration branch before its tip
  is an ancestor of `main`.
- Do not delete `apk-downloads` while any doc or release process points at its
  raw URL. Do not delete `codex/apk-size-trial` without the tag or T-194
  closure.
- No product code or schema changes in this task; ADR not needed. Evidence
  recorded here is repository metadata only (no SMS, no personal data).

## Risks

- Integration head moves after CI is green -> merge the exact verified SHA;
  re-run CI if it changes.
- Deleting `apk-downloads` breaks the documented install/download links and
  loses the only copy of historical APKs (the orphan history cannot be
  rebuilt bit-for-bit). Mitigate: move APKs to GitHub Releases first, update
  docs, keep a local archive copy of the last release.
- Bot PRs are re-created by the Jules integration under new branch names.

recommendation: **GitHub Releases** (asset per version, immutable URL),
keeping `apk-downloads` until docs are updated; the alternative is to keep
`apk-downloads` as the single documented exception.
