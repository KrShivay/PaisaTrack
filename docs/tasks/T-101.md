# T-101 — Expected payments and recurring calendar gaps

Status: proposed; implementation is partly present in T-138 code.

## Current state and real gaps

- `ExpectedEvents` stores source, amount/range in paise, currency, date window,
  state, and fulfilled transaction ID ([table](../../lib/data/db/tables/expected_events_table.dart#L5)).
- `ExpectedEventRepository.recordExpectedEvent` deduplicates; reconciliation
  requires exact normalized VPA, same currency, eligible settled debit,
  bounded amount/date, and a unique two-way match. It marks unmatched past
  windows missed and supports snooze/cancel
  ([repository](../../lib/data/repositories/expected_event_repository.dart#L37)).
- `SmsIngestor` routes reminder/mandate-like messages into expected events
  before transaction parsing and reconciles after recording
  ([source](../../lib/capture/sms_ingestion.dart#L347)).
- Named tests cover repeated reminders, range extraction, currency, fulfillment,
  ambiguity, missed, snooze/cancel and ingestion
  ([tests](../../test/data/repositories/expected_event_reconciliation_test.dart),
  [ingestion](../../test/capture/expected_event_ingestion_test.dart)).
- Gap: establish product-visible calendar/list and event edits; test lifecycle
  across correction, deletion, duplicate suppression, source currency changes,
  and restore. Do not rebuild the existing store or matcher.

## Scope and non-goals

Finish expected-payment review and recurrence calendar using existing expected
events. Expected events never become transactions or spending. No automatic
debit creation, broad fuzzy identity matching, or recurrence prediction without
separate validated evidence.

## Slices

### T-101a — Gap and lifecycle audit (~S)

- **Goal:** compare actual expected-event APIs, capture triggers, lifecycle
  corrections, database migration/archive paths and reachable UI against the
  desired user flow.
- **Acceptance evidence:** gap map with source references; named scenarios for
  reminder dedupe, conflicting same-day obligations, exact and ranged amounts,
  price change, missed, snooze, cancel, fulfilled, deletion and restore.
- **Depends:** none; use `expected_event_reconciliation_test.dart` and
  `expected_event_ingestion_test.dart` as characterization anchors.
- **Schema/ADR:** none for audit; ADR first if lifecycle/source semantics or
  persisted fields change; additive migrations only.
- **Privacy:** synthetic electricity/telecom providers such as XBANK; no real
  messages.
- **Rollback:** proposal only.
- **Test strategy:** extend deterministic repository tests; use UTC fixed clock
  and round INR / synthetic USD fixtures.
- **Exact command:** `flutter test --no-pub test/data/repositories/expected_event_reconciliation_test.dart test/capture/expected_event_ingestion_test.dart`.
- **Readiness:** owner accepts calendar scope, event edit rules, and whether
  recurrence series are in this task or remain owned by recurring work.

### T-101b — Calendar/review and explicit event actions (~M)

- **Goal:** expose expected, fulfilled, missed and snoozed state with explicit
  edit/snooze/cancel actions; resolve price changes without rewriting a settled
  row.
- **Acceptance evidence:** `test/data/repositories/expected_event_reconciliation_test.dart`,
  new `test/features/expected_events/expected_events_screen_test.dart`, and
  `test/features/backup/encrypted_backup_service_test.dart` cover restart persistence,
  event/transaction separation, currency- and ambiguity-safe matching; physical
  accessibility evidence if release-critical routes change.
- **Depends:** T-101a; shared UI/accessibility contract T-167/PV-07 as applicable.
- **Schema/ADR:** reuse existing fields where possible; additive schema only
  after ADR and backup coverage review.
- **Privacy:** local-only schedule; avoid notification text exposing amount or
  merchant on lock screen unless existing disclosure policy permits.
- **Rollback:** preserve stored events; hide new route/entry point and keep
  reconciler compatible.
- **Test strategy:** synthetic reminders, event state transition table, duplicate
  scans, ambiguous debit candidate, source-currency mismatch, backup round-trip.
- **Exact command:** `flutter test --no-pub test/data/repositories/expected_event_reconciliation_test.dart test/features/expected_events/expected_events_screen_test.dart test/features/backup/encrypted_backup_service_test.dart`.
- **Readiness:** all current lifecycle call sites and restore behavior mapped;
  UX copy and notification disclosure resolved; rollback retains user edits.

### T-101c — Missed/price-change follow-up (~S)

- **Goal:** add only the follow-up actions required by T-101a/b; never silently
  classify changed amounts as fulfillment.
- **Acceptance evidence:** threshold/date-window tests, stale-event conflict and
  Undo/reopen behavior where approved, in
  `test/data/repositories/expected_event_reconciliation_test.dart` and
  `test/features/expected_events/expected_event_follow_up_test.dart`.
- **Depends:** T-101b and product decision from audit.
- **Schema/ADR:** no migration unless lifecycle requires new durable state.
- **Privacy:** synthetic fixtures.
- **Rollback:** additive state retained; disable new transition controls.
- **Test strategy:** boundaries immediately before/after due window, changed
  amount, competing events and candidate debit.
- **Exact command:** `flutter test --no-pub test/data/repositories/expected_event_reconciliation_test.dart test/features/expected_events/expected_event_follow_up_test.dart`.
- **Readiness:** state machine has no silent terminal transition; owners agree
  on price-change action.
