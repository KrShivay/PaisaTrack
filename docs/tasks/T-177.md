### T-177a progress — threshold evidence safeguard

The existing threshold recomputation treated every `status='auto'` row as a
correct outcome. This is invalid because silence is not a user-confirmed label.
The safeguard now considers category corrections and explicit confirmation
feedback linked to category prediction provenance. Status-only confirmations,
manual entries, and unreviewed automatic rows do not lower the threshold. The
adaptive metadata key is versioned so values trained by the old silence rule
are discarded and the static threshold is used until enough eligible evidence
is collected. Deterministic fingerprints cover completed chronological
50-outcome cohorts; feedback revisions replay all completed cohorts from the
static default. If undo or a category change leaves fewer than 50 eligible
outcomes (or removes the category entirely), the learned value, count, and
fingerprint are cleared and the static threshold is used. The stored cohort
fingerprint is a streaming SHA-256 digest rather than a copy of the event list.

This is only a verified safety milestone, not completion of T-177a. The
transaction detail now has a separate evidence-backed parse-confirm action;
that event records parser feedback only and does not confirm the transaction,
change its category, or count as category-threshold evidence. v1 and v2
threshold/count metadata are ignored by the v3 evidence-fingerprint state.
Live/historical/resumed provider paths, T-140/T-143 reconciliation, evidence
coverage, cohort sizes, precision, and accuracy/coverage baselines remain to be
audited. The parse-confirm event uses a versioned marker; the public-template
ledger ignores legacy unvalidated positive rows, filters invalid/deleted/
duplicate evidence, rebuilds stale v1 cache on first read, and keeps confirmed
evidence after raw SMS retention expires. This provenance milestone does not
complete T-177a.

## T-177b — Connect safe identity and confirmed-history memory [P1]

- Depends: T-177a. Anchors: `Categorizer`, `MerchantResolver`,
  `CounterpartyKeyParser`, `DecisionPolicy`, `FinancialEligibility`.
- Supply bounded confirmed-history memory through production providers. Preserve
  explicit rule priority; distinguish mixed-use payees and identity ambiguity.
- Review P2P defaults: a person's VPA alone must not exclude a purchase from
  spending. Do not silently merge fuzzy payees or rewrite source facts.
- Acceptance: repeated/new/mixed/conflicting payees, same-name different VPAs,
  shopkeeper personal VPA, missing model and reimport tests. User edits win;
  unsafe candidates abstain; live and historical paths agree.
