# T-102 — Local statement import and reconciliation

Status: proposed; script support is not an in-app import feature.

## Current state and real gaps

- Architecture explicitly calls for local preview, source fingerprinting and
  guarded reconciliation and says not to bypass `SmsIngestor` invariants
  ([boundary](../architecture.md#future-extension-boundaries)).
- [`scripts/reconcile_statement.py`](../../scripts/reconcile_statement.py) is an offline analysis script with ref,
  amount/balance/date and unique-amount matching; it emits row-level results
  and accepts spreadsheet inputs. It is not a product import flow and must not
  be used with personal statements in this planning run.
- Transaction rows store source-channel, currency, reference and lifecycle
  fields ([schema](../../lib/data/db/tables/transactions_table.dart#L30));
  `transaction_links` represents relationships
  ([schema](../../lib/data/db/tables/transaction_links_table.dart#L6)).
  **Unverified:** no in-app CSV preview, statement fingerprint/import ledger,
  account mapping, idempotent commit or user ambiguity-resolution flow was
  verified.
- Gap: define supported export profile, source identity/fingerprint, import
  provenance, duplicate-window handling, transaction creation boundaries,
  correction protection, undo, retention and backup/delete behavior.

## Scope and non-goals

Import a documented CSV export locally through preview, explicit account
mapping, guarded match review, and transactional apply/undo. Preserve statement
rows as evidence and never overwrite SMS-derived source fields or user edits.
No bank login, network sync, XLSX support in the first slice, or auto-created
settled transaction absent a clear policy.

## Slices

### T-102a — Source and fingerprint contract (~M)

- **Goal:** define CSV dialect/profile, columns, dates/timezone, debit/credit,
  currency, stable source row identity, account mapping, fingerprint and
  duplicate import behavior.
- **Acceptance evidence:** synthetic CSV samples for XBANK with `XX1234` and
  round amounts; spec includes malformed rows, duplicate statement windows,
  missing refs, mixed currency, repeated amounts and conflicting balances.
- **Depends:** none for audit; coordinate T-100 net-accounting and T-190h card
  statement boundaries. See [T-100's scope note](T-100.md#dependencies-and-readiness).
- **Schema/ADR:** ADR before durable import ledger or schema; additive only.
- **Privacy:** synthetic statement records only. Never read `BankStatement/`,
  `Library/`, Downloads or live data.
- **Rollback:** proposal only; no source changes.
- **Test strategy:** parser fixture contract; hashes/fingerprints stable across
  row order only if the approved semantics say order is irrelevant.
- **Exact proposed command:**
  `flutter test --no-pub test/features/statement/statement_csv_parser_test.dart`.
- **Readiness:** supported CSV format, account identity, duplicate-import and
  evidence-retention rules accepted; schema/backup/delete diff reviewed.

### T-102b — Parse and preview (~M)

- **Goal:** parse locally, validate and preview additions, candidate links,
  ambiguity and excluded rows before any database mutation.
- **Acceptance evidence:** named parser/widget tests for malformed/large files,
  duplicate rows, same-amount dates, exact refs, balance conflict, mismatch and
  user-corrected transaction protection.
- **Depends:** T-102a; T-100a source/net policy; T-165c monetary migration
  design if amount storage is affected.
- **Schema/ADR:** prefer transient preview state; ADR/migration if durable
  idempotency or provenance rows are required.
- **Privacy:** local parse; no statement content in logs, crash text or metrics.
- **Rollback:** preview has no writes; cancel discards transient data.
- **Test strategy:** synthetic `XBANK`, masked account and integer-cent fixtures;
  fuzz malformed CSV without external data.
- **Exact proposed command:**
  `flutter test --no-pub test/features/statement/statement_csv_parser_test.dart test/features/statement/statement_import_preview_test.dart`.
- **Readiness:** every preview row has a deterministic status and user choice;
  ambiguous matches cannot apply silently.

### T-102c1 — Atomic apply and import idempotency (~M, re-estimate at grooming)

If the import ledger needs schema, migration and both archive encodings, split
schema/migration/backup (T-102c1a) from atomic apply/idempotency (T-102c1b)
before Ready.

- **Goal:** commit approved links/imported records atomically and prevent repeat
  import. This slice owns new durable import state and its migration.
- **Acceptance evidence:** transaction-failure rollback, same file re-import,
  overlapping statement windows, correction preservation and exact counts of
  applied/linked/skipped rows, using
  `test/features/statement/statement_import_repository_test.dart` and
  `test/data/db/app_database_statement_import_migration_test.dart`.
- **Depends:** T-102b, ADR, T-100 approved relationship semantics, PV-04
  explanation contract.
- **Schema/ADR:** additive migration only; backup both archive encodings,
  restore ordering, foreign-key validation and reset/delete coverage are part
  of c1 persistence acceptance.
- **Privacy:** imported evidence is financial data; retain only the minimum
  needed, under encrypted local database/backup policy. No cloud or telemetry.
- **Rollback:** failed apply is transactional; retain import provenance for
  compatibility and later undo.
- **Test strategy:** synthetic per-row provenance, failure injection,
  idempotent archive round-trip and migration upgrade.
- **Exact command:** `flutter test --no-pub test/features/statement/statement_import_repository_test.dart test/features/backup/encrypted_backup_service_test.dart test/data/db/app_database_statement_import_migration_test.dart`.
- **Readiness:** apply transaction boundaries, durable ownership and migration
  are reviewed.

### T-102c2 — Review decisions and import undo (~M)

- **Goal:** let users review ambiguous reconciliation and undo only
  import-owned changes without reverting later user edits.
- **Acceptance evidence:** synthetic review tests cover conflicting candidates,
  stale decisions, undo after restart, later user edits, and partial rollback;
  use `test/features/statement/statement_import_review_test.dart` and
  `test/features/statement/statement_import_undo_test.dart`.
- **Depends:** T-102c1 and T-102b; retain the PV-04 explanation contract from
  c1 for the reviewed result.
- **Schema/ADR:** no new schema beyond c1 unless the audit proves necessary;
  any added durable decision state requires backup/restore and migration tests.
- **Privacy:** synthetic XBANK rows only; no statement content in logs,
  diagnostics or metrics.
- **Rollback:** undo only importer-owned changes and retain later user edits.
- **Test strategy:** preview/apply/review/undo state table with synthetic rows.
- **Exact command:** `flutter test --no-pub test/features/statement/statement_import_review_test.dart test/features/statement/statement_import_undo_test.dart test/features/backup/encrypted_backup_service_test.dart`.
- **Readiness:** conflict behavior and undo ownership are reviewed; review can
  resume safely after restart.

## Files likely touched

New statement parser/preview/repository/UI under `lib/`, `transaction_links`
or additive import-ledger table, encrypted backup service, synthetic CSV
fixtures under `test/fixtures`, and focused parser/repository/widget/migration
tests. Keep `scripts/reconcile_statement.py` as a separate analysis tool unless
an explicit implementation task chooses to share pure parsing code.

T-190h coordinates card statement snapshots. Before Ready,
settle CSV scope, fingerprints, source-row immutability, ambiguous matching,
backup and Undo.
