## Shared implementation contract

- Preserve local-first behavior, raw-SMS retention, source rows, source amounts and source currency. Use synthetic SMS/statements and disposable databases only.
- Exactly one canonical liability delta per source event. Allocated payment confirmations, linked return/reversal/refund credits, classified cashback and EMI conversion credits are excluded from generic posted-credit application. Use the scenario map and sequence assertions in the plan as the accounting oracle.
- A purchase `reverses` credit nets the purchase in its original period. A `refunds` credit follows the separately approved refund-period policy. Do not treat these link types as interchangeable.
- Keep current `FinancialEligibility` settled/nonduplicate/nonexcluded/nontransfer rules as the base; make net spend consistent across consumers. Card payment is never spend.
- Any schema change requires an accepted ADR, additive migration, generated schema, backup/restore, reset/delete, foreign-key and undo coverage. No child brief grants schema approval.
- Each implementation child runs its named focused test command, `flutter analyze --no-pub`, full `flutter test`, and `git diff --check`. Synthetic evidence is not device acceptance.
- Preserve unresolved owner decisions and release gates. Rollback must retain source rows and durable user decisions.
