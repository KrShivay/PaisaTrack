# T-193 — Repair legacy currency from retained evidence

Status: Backlog. Do not implement until separately started.

The installed v2006 predates T-187. Current parsing maps `Rs.` to INR, but the
v18 migration leaves existing null-currency transactions unchanged, and
`ingestBatch` skips SMS IDs already present. A later safe repair must use the
retained source message and exact matching evidence rather than re-ingestion or
merchant/locale guesses.

## Safety contract

- Preview only transactions whose currency fields are still null.
- Accept only an exact adjacent `Rs.`, `INR`, or `₹` marker in the retained SMS
  and a message amount that matches the persisted transaction amount.
- Never overwrite known currency fields or infer from merchant, locale, or
  another transaction.
- Rows with purged/missing source text, ambiguous markers, or amount mismatch
  remain unknown and are reported as unrecoverable by this repair.
- Applying a preview is a user action and must be reversible, restoring the
  prior null values. No automatic changes during migration, restore, or startup.

## Acceptance

- New `Rs.` messages still parse as INR.
- Preview does not mutate rows; confirmed apply changes only null currency
  fields on exact source/amount matches.
- Undo restores the original null fields. Repeating the action is idempotent.
- Cover already-known SMS IDs, duplicate SMS, retained and purged messages,
  amount mismatches, ambiguous currency markers, backup/restore, and rollback.
- Tests use synthetic messages only; never log or export raw SMS during repair.

Dependencies: T-187 currency parsing behavior and repository duplicate handling.
Rollback: disable the repair entry point; existing transaction amounts and
source rows remain unchanged, and applied changes are reversible through Undo.
