# T-193 — Repair legacy currency from retained evidence

Status: In Review.

The installed v2006 predates T-187. Current parsing maps `Rs.` to INR, but the
v18 migration leaves existing null-currency transactions unchanged, and
`ingestBatch` skips SMS IDs already present. This task adds a user-triggered,
per-transaction preview and reversible repair in transaction detail. It must
work for restored databases without relying on a schema migration.

## Safety contract

- Preview only transactions whose currency code and symbol are both null.
- Accept only an exact adjacent `Rs`, `Rs.`, `INR`, or `₹` marker in retained,
  unexpired linked SMS and amount evidence whose bounds and verbatim text match
  the body and whose parsed value equals the persisted amount to the paise.
- Allow template, generic, and local-LLM SMS records only when their persisted
  amount evidence passes those checks. Skip manual, imported/unknown, missing
  source, deleted, duplicate, and not-transaction rows.
- Require exactly one adjacent recognized marker. This repair is INR-only;
  USD/US$ and ambiguous bare `$` are not repaired.
- Never overwrite known currency fields or infer from merchant, locale, or
  another transaction.
- Rows with purged/missing/expired source text, invalid evidence, ambiguous
  markers, or amount mismatch remain unknown.
- Apply revalidates the preview in a database transaction and changes only
  currency code/symbol. Undo clears those values only if they still equal the
  repair result, preserving later edits.
- No automatic changes during migration, restore, or startup.

## Acceptance

- New `Rs.` messages still parse as INR.
- Preview does not mutate rows; a confirmed per-transaction apply changes only
  null currency fields on exact source/amount matches.
- Undo restores the original null values. Repeating apply is idempotent.
- Cover template/generic amount evidence, already-known SMS IDs, duplicate SMS,
  retained and expired messages, amount mismatches or edits, pre-set currency,
  ambiguous markers, backup/restore, idempotence, and guarded undo.
- Tests use synthetic messages only; never log or export raw SMS during repair.
- Encrypted chunked-backup integration test restores synthetic retained and
  expired legacy rows through `EncryptedBackupService`. Retained raw SMS and
  amount evidence still support preview/apply/undo; expired SMS is omitted,
  detached from its transaction, and remains ineligible.

## Review status

The source-backed repair received independent review with no blocker. The
encrypted restore compatibility test and this task follow-up await independent
review. Physical transaction-detail preview/apply/undo confirmation remains
pending on the user's device.

Dependencies: T-187 currency parsing behavior and transaction-detail Undo.
Rollback: disable the detail action; no migration or re-ingestion changes
existing transaction amounts or source rows, and applied repairs are reversible
through Undo.
