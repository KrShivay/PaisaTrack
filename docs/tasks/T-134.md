# T-134 — Financial events and the link graph

`txn_<smsId>` hard-codes one SMS to one transaction, but real events span
messages. The 10-minute dedup window cannot reach an auth→settle gap, and
counterparty comparison uses substring `contains`, so `AMAZON` matches
`AMAZONPAYLATER`.

### T-134a — Schema   [P1] [~M]
Files:    `lib/data/db/tables/financial_events_table.dart` (new),
          `lib/data/db/tables/transaction_links_table.dart` (new),
          `lib/data/db/database.dart`
Depends:  T-132a
Change:   `financial_events` (id, event_key unique, key_basis, kind, net_amount
          **INTEGER paise**, currency, opened_at, closed_at, state, confidence)
          and `transaction_links` (from/to txn, link_type ∈ echo|settles|
          reverses|refunds|repays|transfer_leg|fulfills, confidence, basis,
          created_by, created_at). Every new monetary column is paise — T-130
          owns the legacy `amount REAL` migration; do not add to that debt.
Tests:    Migration test; foreign keys resolve; unique event_key enforced.
AC:       Additive. No existing query changes.

### T-134b — Correlation key ladder   [P1] [~L]
Files:    `lib/data/dedup/duplicate_match_rule.dart:44-63`,
          `lib/capture/event_correlator.dart` (new)
Depends:  T-134a, T-143b sequence fixtures
Change:   Ordered ladder, first match wins, no match is not an error:
          (1) `ref` ±30d — normalize UTR to the longest digit run ≥9, never match
          a ref under 6 chars; (2) `auth` ±5d on card_last4|merchant|amount ±2%;
          (3) `reversal` ±30d opposite direction; (4) `echo` ±10min (existing
          semantics, unchanged); (5) `transfer` ±60min between owned sources.
          **Replace `_sameCounterparty`'s substring `contains`** with exact match
          on the structured identity key, falling back to normalized-prefix with
          a minimum length and a token boundary.
Tests:    Distinct payments with different ref ids are **never** merged — ref
          disagreement vetoes the echo rule. Auth and settlement collapse across
          days. `AMAZON` does not match `AMAZONPAYLATER`.
AC:       Merging two real payments is the worst dedup failure; precision ≥0.999.
Note:     `~L`. Split per key tier if needed.

### T-134c — Materialized projections   [P1] [~M]
Files:    `lib/capture/duplicate_suppressor.dart`, `lib/capture/sms_ingestion.dart`
Depends:  T-134b
Change:   Keep `duplicate_of_txn_id` and `owned_transfer_id` as denormalized fast
          paths maintained in the same write transaction as the link rows. The
          graph is the source of truth; the columns preserve every existing query
          and index. Replace the O(n²) owned-transfer scan (T-130) with an indexed
          SQL join on (amount_paise, ts bucket, direction).
Tests:    Column and graph never disagree. ADR 0003's guarantee holds: suppression
          links, never deletes.
AC:       No analytics query is rewritten by this task.
Rationale: `docs/sms-intelligence-design.md` §7.2.
