# T-195 — Keep source SMS provenance (owner decision)

## Owner decision (2026-10-03)

The owner, who is the app's only user, asked why old transaction SMS disappear
from the detail screen's "Where this came from" section and said the
30-day removal policy is not wanted. Source SMS that back a transaction (or a
"not a transaction" disposition) must be kept indefinitely.

## Current behaviour (code facts)

- `AppConstants.rawSmsRetentionDays = 30`, feature flag
  `raw_sms_retention_days`, column `raw_sms.purge_after` set at capture
  (`lib/capture/sms_ingestion.dart`).
- `NightlyStage.purgeExpiredRawSms` (`lib/intelligence/nightly_job.dart`)
  deletes expired `raw_sms` rows and first sets `transactions.sms_id` to NULL.
- Backups include only rows with `purge_after` in the future
  (`lib/features/backup/encrypted_backup_service.dart`); currency repair
  (`source_currency_repair_service.dart`), `raw_sms_repository.dart` and the
  unreadable-SMS screen copy also rely on expiry.

## Scope

1. Stop deleting or unlinking source SMS of transactions/dispositions; backups
   include them; provenance and repair code no longer treat them as expired.
   Decide and document the policy for SMS that never became a transaction.
   Prefer no schema change; otherwise ADR + additive migration + tests.
   Settings "Delete everything" and per-row deletion keep working.
2. ADR 0021 "Retain source SMS provenance" (Accepted, owner decision);
   update `docs/privacy.md`, `docs/decisions/README.md`; record backup-size
   impact against ADR 0008. Reconcile T-169b and T-170b, which still describe
   expiry.
3. Re-link provenance already purged: user-invoked or idempotent re-read of
   the device inbox through the existing history-import reader (no new
   permission), re-creating `raw_sms` and re-linking only on an exact
   deterministic match; never create transactions or change amounts or
   categories; ambiguous rows are skipped and counted.
4. "Where this came from" shows the SMS whenever it exists.

## Acceptance

Regression tests fail before the fix; nightly job keeps linked SMS; backup
round-trip includes old SMS; re-link test with synthetic inbox (match, skip,
ambiguous); full suite, analyze, format, detect-changes. Physical check on the
owner phone: a transaction older than 30 days shows its SMS after re-link.

## Privacy and rollback

Data stays on device inside the encrypted database and encrypted backups.
Rollback: restore the purge stage (no data loss beyond today's behaviour).
