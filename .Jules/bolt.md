## 2024-05-18 - Optimize transaction list filtering performance
**Learning:** In Dart/Flutter, unconditionally creating new string objects inside a tight loop (like converting 10 properties to lowercase for every item in a large list on every keystroke) generates significant garbage collection pressure and can cause UI jank. Eager boolean evaluation in search filters exacerbates this by computing comparisons that are ultimately unnecessary if an earlier field already matches.
**Action:** When filtering large lists locally, hoist loop invariants (like `query.toLowerCase()`) out of the `.where` callback. Refactor eager logical combinations (e.g. `!a && !b && !c`) into short-circuiting conditional chains (e.g. `if (a) return true; if (b) return true;`) so that string allocations and comparisons are skipped as soon as a match is found.
